## Repository Verification

The repository has two GitHub Actions workflows:

- `.github/workflows/python-ci.yml` installs the package from a clean checkout,
  compiles `src/` and `tests/`, runs `python -m trustai demo` to generate the
  bundled aitrade proof pack, verifies it offline, generates, verifies, appends, and chain-verifies the
  roadmap audit, checks root unittest discovery for the importable `tests/`
  package, and runs clean-checkout smoke tests for proof packs, ingestion,
  re-execution, verifier releases, verifier distribution, Go verifier release
  workflow controls, roadmap coverage, external evidence manifests, semantic roadmap evidence chains, roadmap evidence reports, self-contained roadmap evidence bundles, and standards
  metadata.
- `.github/workflows/go-verifier.yml` tests the dependency-free Go verifier
  source and cross-builds static verifier artifacts with checksum, SBOM,
  provenance, and hosted build-attestation hooks.

The full local suite also verifies downstream receipt types that depend on the
long generated artifact chain documented below. Generated `.trustai/` state,
`artifacts/`, caches, and build outputs are intentionally ignored by Git. Retained external-evidence artifacts under `examples/aitrade/external-evidence/` include a current coverage manifest, retained collected-source map, retained collection-run report, remaining collection plan, source-map template, and gap report with placeholder/live source URI counts for the 67 authority units still requiring live external evidence.

## Local API

```powershell
$env:PYTHONPATH = "src"
python -m trustai serve --host 127.0.0.1 --port 8080 --state .trustai/server/evidence-chain.json --tenant local

$env:TRUSTAI_ENDPOINT = "http://127.0.0.1:8080"
& "C:\Users\moham\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" examples/aitrade/typescript_capture.mjs
```

The server also exposes `POST /v0/provider-lifecycle-operations` for local
provider OAuth/token/revocation operation receipts. Protect it with
`--provider-lifecycle-operation-token env:TRUSTAI_PROVIDER_OPERATION_TOKEN` when
recording provider lifecycle operations over HTTP.

The default signer and `.trustai/keyring.local.json` are local HMAC developer
stand-ins. They model provider/key-id verification for `local-kms`,
`local-tsa`, and `local-dev`, but production deployments still need
customer-controlled KMS/HSM-backed signatures and independent timestamp
authority integration.

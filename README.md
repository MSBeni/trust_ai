The codebase is intentionally self-contained. It implements the core proof
workflow from the roadmap without requiring network access or external services:

1. Register a Verification Contract before testing starts.
2. Append the registration to a signed, timestamped, hash-chained Merkle log.
3. Record agent inventory from manual files or identity exports, plus multi-agent delegation evidence.
4. Ingest OTel-style GenAI trace events with files, API, OTLP JSON traces, framework-native traces, or Python/TypeScript SDKs, plus MCP tool-call transcripts, and publish signed collector topology manifests for the ingestion/MCP/control-plane path.
5. Attest high-risk runtime actions against blast-radius policy.
6. Evaluate shadow replay, local runner-orchestrated repeated re-execution runs, re-execution isolation attestations, temporal holdout data, soak windows, thresholds, and signed human approval evidence.
7. Emit a signed promotion gate decision.
8. Compile a portable JSON proof pack and human-readable PDF.
9. Evaluate runtime policy and proof decay for high-risk actions, then sign policy engine decision receipts, policy backend enforcement receipts, and policy backend service hardening attestations for OPA/Cedar export and hosted-backend evidence.

## Repository Verification

The repository has two GitHub Actions workflows:

- `.github/workflows/python-ci.yml` installs the package from a clean checkout,
  compiles `src/` and `tests/`, runs `python -m trustai demo` to generate the
  bundled aitrade proof pack, verifies it offline, generates, verifies, appends, and chain-verifies the
  roadmap audit, and runs clean-checkout smoke tests for proof packs, ingestion,
  re-execution, verifier releases, verifier distribution, Go verifier release
  workflow controls, roadmap coverage, external evidence manifests, semantic roadmap evidence chains, roadmap evidence reports, self-contained roadmap evidence bundles, and standards
  metadata.
- `.github/workflows/go-verifier.yml` tests the dependency-free Go verifier
  source and cross-builds static verifier artifacts with checksum, SBOM,
  provenance, and hosted build-attestation hooks.

The full local suite also verifies downstream receipt types that depend on the
long generated artifact chain documented below. Generated `.trustai/` state,
`artifacts/`, caches, and build outputs are intentionally ignored by Git.

provider OAuth/token/revocation operation receipts. Protect it with
`--provider-lifecycle-operation-token env:TRUSTAI_PROVIDER_OPERATION_TOKEN` when

authority integration.
